core/ — The AI engine

CORE
Pure Python. No Flask, no SQLite, no HTTP. Everything in here is callable by app.py, api_v1.py, main.py (CLI), and evals — without booting a server. The boundary that earns the "kernel" name: any external LMS can call these functions directly.

Curricula & Question Bank

CURRICULA
Each curriculum lives in its own directory. The tutor loads the question bank on every session start and injects up to 20 questions into the system prompt so the AI can quiz students from real questions.

Past Paper Import — Question extraction

CURRICULA
Teacher pastes a URL from an allowed revision site. The server fetches the PDF, core/questions.py extracts text and asks the LLM to copy each real question (swapping variables), then appends them to questions.json. Non-maths subjects only — pypdf corrupts equations.

api_v1.py — Stateless REST API (/v1/)

API
Flask Blueprint registered at /v1/. No cookies, no sessions, no HTML. Callers own their full message history (OpenAI pattern). Auth via Authorization: Bearer token — SHA-256 stored in api_keys table, plaintext never saved. Each route calls directly into core/.

CORE
All shared prompt strings and the signal parser. The [CORRECT]/[WRONG]/[OPEN] instruction and the regex that reads it live side by side here so they can't drift apart. _SIGNAL_RE is anchored to end-of-string — the signal must be the last thing in a reply.

users.py

AUTH
SQLite-backed accounts. Three tables: users, sessions, api_keys. Passwords and API keys both stored as SHA-256 / scrypt hashes — a leaked DB yields no working credentials. Roles: student / teacher / admin. API keys are minted with token_urlsafe(32) and the plaintext is returned once.

evals/run.py
