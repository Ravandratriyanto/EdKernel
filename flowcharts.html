Kernel Architecture — the engine is the product, the UI is swappable

KERNEL
EdKernel is a kernel, not an app. The value is the education-specific orchestration — Socratic tutoring that withholds the answer, per-step error localisation, curriculum-grounded questions, progress and misconception tracking — exposed as composable primitives over the /v1/ API. Reading handwritten maths is not the moat (frontier models already do that); the pedagogical engine is. Any front end builds on the same API: the shipped web UI is just one reference client, like a Linux distro over the kernel. Swap it for a mobile app, an LMS plugin, a bot — the backend contract is fixed. core/ is pure Python with no Flask and no UI; api_v1.py is the only public surface.

OpenCV 5 Pipeline — photo of working → first wrong step

VISION
The perception half of the agentic loop, and the part the competition judges on. A phone photo is rectified, deskewed, binarised and cut into one crop per working line before any model is called. The LLM never sees the raw photo — it sees one line at a time. OpenCV's role here is deterministic spatial grounding — the verifiable box coordinates a vision LLM cannot reliably produce — which lets the system draw a red box on the exact wrong line. A located error is then categorised (coarse tag emitted by the examiner) and fed to the class misconception map. Fires automatically when a student attaches an image in Learn mode.

Student Home & Quiz Mode

OVERVIEW
Picking a class opens a Gojek-style service-tile grid, not the tutor. Quiz mode copies the Digital SAT Bluebook layout and deliberately shows no live right/wrong — teacher feedback was that live marking spikes exam nerves. The answer key never reaches the browser: the server opens an attempt, sends key-stripped questions, and marks the whole thing at submit. Anti-cheat is two layers on one counter: tab-switch detection (visibilitychange) plus a forced-fullscreen layer (session 36) — fullscreen can't block Alt+Tab/Cmd+Tab, no webpage can, but it hides everything else so a casual peek isn't a click away, and leaving it (Esc, or the OS auto-exiting on an app switch) trips the same counter, de-duped so one real switch isn't counted twice.

Progress Tracking — mastery per topic

AUTH
A SQLite table in users.py, written only from a server-side comparison against the stored answer key. Mastery is correct/attempts, rendered as a coloured dot on the topic list and used to pick the Continue recommendation. Right and wrong both count, once per question per attempt. A companion misconceptions table (written by the OpenCV step checker, not by MCQ answers) aggregates why students were wrong into the class misconception map.

Past Paper Import — Question extraction

CURRICULA
Teacher pastes a URL from an allowed revision site. The server fetches the PDF, core/questions.py extracts text and asks the LLM to copy each real question (swapping variables), then appends them to questions.json. Non-maths subjects only — pypdf corrupts equations.

api_v1.py — Stateless REST API (/v1/)

API
Flask Blueprint registered at /v1/. No cookies, no sessions, no HTML. Callers own their full message history (OpenAI pattern). Auth via Authorization: Bearer token — SHA-256 stored in api_keys table, plaintext never saved. require_auth also enforces a 20-call/minute ceiling per key owner, so a leaked key cannot run up unbounded model spend. app.py's before_request lets the blueprint past the cookie gate — without that, every Bearer caller got a 401.
